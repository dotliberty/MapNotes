# MapNotes 1.3.0

## New in this release

- Record walking, running and transport within one journey, with separate movement labels and statistics. Transport is recorded without unlocking the exploration map.
- Open **Map menu → Movement** for Auto/manual recording mode, a colored route schematic, journey selection, interval corrections and last-correction undo.
- Optional Google activity recognition provides movement observations. Walking/running is not selected by a universal speed cutoff. Without available Google Play services or physical-activity permission, recording and manual mode remain available.
- Local personal adaptation uses only explicitly confirmed walking/running intervals. Automatic predictions never confirm themselves. Overlapping speed ranges remain ambiguous; a specific sensor label is not replaced solely by speed.
- Profile reset preserves routes, photos and notes. Correction retracts affected training. Independent learning requires three recorded journeys per class; splitting one recording does not manufacture independent samples.
- Existing Java app retained; new movement logic uses Kotlin, with a shared Gradle application/test build and pinned Java/Kotlin formatters.

## Install and update

Download **`MapNotes-1.3.0.apk`** and **`SHA256SUMS`**. This is the official non-debug app, package `ru.main.explorer`, versionCode **39**, target SDK **35**, signed with the established release certificate verified against 1.2.4.

Install over the previous official version. **Do not uninstall or clear app storage.** SQLite v3 → v4 adds movement data without intentionally deleting previous routes, photos or notes. Older records remain unclassified rather than being invented walking/running labels. A separate debug app is not replaced and its test data is not imported automatically.

## First mixed journey

1. Open **Map menu → Movement**.
2. Choose Auto and allow physical-activity recognition, or select Walking, Running or Transport manually.
3. Return to the map and explicitly start recording. Choosing a movement mode does not start recording on its own.
4. Inspect the recorded journey from Movement or walk history. Correct intervals as needed. Explicit learning confirmation is a separate action, not an automatic effect of recording manually.

## Verification and limitations

This is published as a **stable GitHub release at the owner's explicit request**, not as a prerelease. Recognition quality and personal adaptation remain experimental: a stable release label is not evidence of completed physical-device acceptance.

- Final full run: **35 suites, 301 Android/JVM tests, 298 passed, 3 external-data opt-in tests skipped, zero failures/errors**. These include actual SQLite migration/rollback, recording service, movement events, manual corrections/profile persistence and Native Canvas UI tests.
- Formatting gate, EN/RU audits, pure geometry/GPS checks, metadata and signing-policy tests passed.
- Official APK: signature continuity with 1.2.4, package/version/non-debug flag, ZIP CRC and zip alignment verified.
- **No connected phone was available for field acceptance.** Walking/running accuracy, real screen-off event delivery, battery use and an actual user-database update remain unverified. Review the detailed limits before relying on automatic labels.
- No universal detection-accuracy percentage, continuous automatic recording start, complete journal backup or fine-grained transport subtype recognition is promised. Transport exploration layers are not introduced.
- User-defined spawn zones are planned separately for **1.3.1** and are **not included** in 1.3.0.
