## Implemented

- Shared root Gradle build for existing Java and new Kotlin, using the historical `render-tests` application module for both packaging and tests. Pins: Gradle 8.9, AGP 8.5.2, Kotlin 1.9.23, Play services Location 21.3.0. Existing Java screens, camera and map were not rewritten; no Compose/Room migration.
- `tools/build.py` invokes the shared Gradle APK tasks, then existing SDK alignment/signing/verification. Debug signing requires the existing persistent local debug key. No key generation and no release credentials are used for debug.
- Optional runtime recognition via Activity Recognition sampling updates, requested at 5 seconds only while explicitly recording in Auto mode. This is a requested interval, not guaranteed delivery. SDK libraries are packaged in the APK; installed Play services and activity permission are optional at runtime. No separate no-Google build flavor is claimed.
- Main-looper event owner, freshness/order checks, confidence gate, sustained candidates, manual override, registration-generation guards and cleanup. Separate PendingIntents prevent a delayed obsolete registration from removing a newer one. Delayed registrations are removed after stop.
- WALK / RUN / VEHICLE / UNKNOWN and ON_FOOT without a forced walking/running subtype. No universal speed boundary between walking and running. STILL retains a recent underlying mode rather than inventing walking at a traffic stop.
- Mixed-journey GPS filter independent of classification. Quality, monotonic time, mock/freshness and implausible-jump checks remain. The 120 m/s sanity ceiling is a transport-quality bound, not a walking/running threshold. A gap over 10 seconds starts a new recording session without joining across it.
- SQLite v4 adds `motion_points` metadata and explicit `motion_samples`; existing points, walks, sessions, photos and notes retain their identities. Coordinates and motion metadata are inserted in one transaction. Legacy records remain unclassified.
- Dedicated Movement screen from the map menu and each walk detail: persistent manual/Auto recording mode, permission request, profile counts/toggle/reset, journey selector, colored route schematic, per-type distances/moving/stopped time, paged segment controls, interval correction with two point-range sliders, explicit learning confirmation and last-correction undo.
- Schematic is explicitly not a geographic basemap. All journey coordinates remain stored. Transport and fully unknown points do not reveal exploration. Persisted foot-point IDs prevent the renderer bridging across excluded vehicle/unknown points. Returning from Movement reloads main exploration after explicit corrections.
- Existing timeline distance includes transport for new mixed journeys; legacy-only distance keeps historical calculation behavior. No segment edge is counted twice. Destination-point labels own boundary edges. Gaps/session boundaries contribute no invented edge. Stop flags suppress GPS jitter distance; stop estimation remains experimental.
- Local personal profile: only explicit confirmations, quality filtering, capped quantile contributions, robust separate walking/running ranges, overlap remains unknown. It refines ambiguous ON_FOOT only, never overrides a specific sensor label solely by speed.
- Profile requires at least three independently recorded journeys per class, one contribution per journey/class. Confirming a different valid interval of the same journey/class replaces that contribution. Duplicate confirmations cannot inflate readiness. Correction retracts overlapping training; undo restores it; reset preserves the journal. Manual recording alone does not train the profile.
- Kotlin-aware EN/RU resource audits and pinned ktfmt 0.53 Kotlin-language style, with JAR SHA256 validation. Formatting covers Java/Kotlin, tests, Python, XML and root/module Gradle files.

## Not yet established / beta limits

- `adb devices` returned no connected device. No real installation, walking/running accuracy, vendor background behavior, screen-off delivery, GPS reception, energy use or real-user update acceptance is claimed.
- Sampling API is integrated; Transition API is not additionally wired. Candidate confirmation currently requires at least 3 observations over 10 seconds, no gap over 10 seconds; automatic evidence expires after 60 seconds. Event freshness is limited to 15 seconds. These experimental parameters may leave data unknown under real provider batching and need phone measurements.
- Stop estimates use recent STILL with compatible GPS speed, or reliable low reported speed. Without usable evidence, stationary time cannot be asserted accurately. Neither speed accuracy nor filter bounds are calibrated to a particular phone yet.
- No retroactive candidate-window relabeling is implemented. Early/ambiguous points remain unknown until explicit correction. A GPS-only no-Google walking/running classifier is not claimed.
- Map transport-reveal policy remains unapproved. This beta records/shows the transport schematic without unlocking the exploration map; no separate transport reveal layer is implemented.
- Personalization is deliberately conservative and experimental. No promised percentage of recognition accuracy, automatic labeling of all transport subtypes, automatic recording start, cloud sync or complete journal backup is added.
- Undo is the last correction within the current Movement screen session; confirming/resetting the profile invalidates that undo snapshot to avoid overwriting later training. It is not a durable multi-level edit history.
- Journey coordinates are loaded for the selected journey and the current schematic draws them; controls are paged. Large-history memory/frame-time optimization and hardware profiling remain open. No pagination/performance guarantee for arbitrarily large journeys is claimed.

## Device acceptance

For field acceptance, use a disposable device/database or retain the separate debug app; do not uninstall or clear the official app. Open map menu → Movement. Allow activity recognition if desired, choose Auto or a manual mode, return to the map and explicitly start recording. Test ordinary/fast walking, slow/ordinary running, transport and stops, then inspect the saved journey. Explicitly confirm only clean homogeneous intervals for learning. Repeat on held-out journeys, compare labels with manually recorded intervals, test denied/revoked permission and screen-off delivery. These observations are still pending; the subsequent stable-publication instruction does not turn them into completed tests.
