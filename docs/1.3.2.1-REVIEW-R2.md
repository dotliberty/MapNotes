## Подтверждённые локальные дефекты

1. Готовый disk viewport терял всё покрытие при переходе integer zoom. `AtlasViewport.Request.style` включал zoom, а `replayCoverage` требовал полного совпадения style. В окончательной синтетической сцене при настоящем pinch **14 → 13.875** готовый raster z14 и основной источник ready=1 сохранялись, но coverage становился **0**. Холодный сосед был отдельным, существующим источником, его импорт независимо задержан. Это потеря готовой геометрии, а не отсутствие данных основного источника.
2. `MapView` подавлял запрос линии и обновление желаемого mask viewport на всём pinch. При текущем **z15** `RouteLines.wanted.zoom` оставался **14** до завершения жеста. Это отдельно воспроизведено с заблокированными line/mask workers.

Диагностический этап компилировался без изменения replay/guards. Затем получены падающие проверки и trace. Для контрольного повтора окончательной сцены прежние zoom-style и pinch-guards временно восстановлены: **5 тестов, 2 failed**, остальные 3 прошли. После возврата исправлений — **5/5 passed**. ## Исправления

- `AtlasViewport` отделяет совместимость replay-стиля от точного zoom запроса. Точный request/dependency key по-прежнему содержит zoom; устаревшая работа отменяется при смене zoom. Готовый raster обоих проходов масштабируется вокруг географического центра. Покрытием считается только проекция прежнего прямоугольника на текущий видимый экран.
- Проверки source key/stamp/bounds/order сохранены. Изменённый или удалённый источник вычитает свой прямоугольник из fallback; новый холодный сосед вычитает только пересекающуюся полосу. Новые пиксели за пределами прежнего raster не объявляются готовыми.
- `MapView` запрашивает независимую линию и обновляет желаемые параметры mask во время настоящего pinch. Прежняя отсрочка для программного `viewportMotion` сохранена. Line worker остаётся coalesced, mask worker по-прежнему один; line не публикуется как reveal.
- Ревизия mask проверяется перед публикацией. При замене atlas очищены готовая маска и её история, чтобы старые стены/раскрытие не возвращались через fallback.

Бюджеты **24 MiB ready / 32 MiB work** не увеличены. Существующее уменьшение raster на больших экранах сохранено.

## Диагностика и ручной экспорт

Новый `MapTrace` хранит последние **2048** числовых событий в заранее ограниченном кольце. В записи — sequence, monotonic `System.nanoTime`, thread ID, фиксированные lane/event, краткоживущий числовой token и три числовых поля. Имена мест, абсолютные координаты, пути источников, названия дорог, URI, фото и пользовательские заметки не записываются. Token — identity объекта в процессе, а не хеш его пути.

Экспорт: меню карты → **«Экспорт диагностики карты»** → системный выбор файла (`ACTION_CREATE_DOCUMENT`). На момент вызова фиксируется ограниченный snapshot, запись выполняется фоновым потоком только в выбранный пользователем URI. Автоматической отправки нет. Проверены запуск picker, request code и побайтовое чтение сохранённого snapshot обратно.

Схема `seq,nanos,thread,lane,event,token,a,b,c`:

| Lane/event | Поля a / b / c |
|---|---|
| INPUT/INPUT | число пальцев / дробный zoom ×1000 / eventTime; token = masked action |
| FRAME/DRAW | дробный zoom ×1000 / base ns / полный кадр ns; token = revision |
| SOURCE/REPLAY | stamp / ready 0–1 / memory=1 или disk=2; token = area identity |
| SOURCE или COLOR/FINISH | backend: tiles=1, viewport=2, geometry=3 / fallback code / loading layers; token = raster revision |
| SOURCE или COLOR/DRAW | backend / loading layers / coverage ×1000 |
| VIEWPORT/QUEUE | zoom / число входных зависимостей / sourcesReady |
| VIEWPORT/REPLAY | zoom готового raster либо −1 / непустое покрытие / точное совпадение |
| VIEWPORT/START | zoom / raster width / raster height |
| VIEWPORT/PUBLISH | vertices / build ns / bytes обоих bitmap |
| VIEWPORT/CANCEL | zoom запроса / текущий zoom / причина: close=1, нет наблюдения=2, zoom=3, style=4, pan=5, dependencies=6 |
| TILE/QUEUE, START, PUBLISH | zoom / color pass / pending count либо duration ns |
| LINE/QUEUE | revision / zoom / accepted point count |
| LINE/PUBLISH | revision / zoom / build ns |
| LINE/DRAW | drawn revision / drawn zoom / текущий zoom |
| LINE/CANCEL | revision / zoom / close-or-clear=1, revision=2, zoom=3, прочее=4 |
| MASK/QUEUE | revision / zoom / accepted point count |
| MASK/PUBLISH | revision / zoom / время от начала worker до UI publication ns |
| MASK/CANCEL | revision / zoom / close=1, atlas=2, world=3, revision=4, zoom=5, pan-or-incomplete=6 |
| COLOR/DRAW с token mask frame | mask revision / mask zoom / complete 0–1 |
| IMPORT/QUEUE, START, FINISH | zoom/flags, queue/readiness и revision/duration согласно месту события |
| IMPORT/SCAN | принятые records / bytes исходного файла / полная длительность импорта ns |
| MONITOR/LOCK | ожидание общего atlas monitor ns / удержание ns / map=0 либо walls=1 |
| MONITOR/SCAN | импортированные records / bytes derived-представления / walls-only 0–1 |
| WALL или VIEWPORT/SCAN | просмотренные records / просмотренный объём derived bytes / cursor lifetime ns |
| WALL или VIEWPORT/FINISH cursor | число принятых records / полный размер derived / zoom |
| WALL/FINISH atlas | число просмотренных областей / число найденных стен, −1 при исключении / полная длительность query ns |

Fallback codes: none=0, disk-source=1, geometry-not-ready-replay=2, tile-work-memory=3, visible-vertex-budget=4, viewport-memory=5, прочее=6. Allocation errors записываются отдельным OOM в tile/viewport/line/mask/import. Ошибка чтения viewport/import имеет ERROR. В конце snapshot — текущие Java used/max и native heap allocated. Это текущие показания, не измеренный peak процесса/GPU.

Пример из финального release-trace: общий monitor — **200 ns ожидания / 5591100 ns удержания**, импорт **2 records / 258 derived bytes**; wall cursors — **3 records / 411 bytes**, длительности в просмотренном trace **139000–263300 ns**. Это небольшая синтетическая wall-сцена, не замер конкуренции/диска телефона. Trace фиксирует ожидание общего monitor отдельно от обхода; ограничение кольца означает, что ранние события длинной записи могут быть вытеснены.

## Регрессия

`MapReviewR2Test` содержит 5 проверок:

1. **110000** пространственно распределённых точек на змейке; каждая соседняя пара проходит `MapView.connects`, то есть сохраняются session/time/sequence/distance. Настоящая disk-сцена с водой, дорогой и зданием; фото; готовый viewport и отдельный холодный, но существующий источник. Начальная установка z14 — только подготовка, дальнейший pan и **14 → 12 → 15 → 14 → 22** идут через настоящие `DOWN / POINTER_DOWN / MOVE / POINTER_UP / UP`. Координаты обоих пальцев остаются внутри 512×512; конечное достижение z22 проверяется явно. Во время движения нет `awaitIdle`/worker barriers. Tile, viewport, line, mask и import задерживаются отдельными latch. В каждом нарисованном sample проверены пиксели известной геометрии обоих цветовых проходов и точная доля пригодного overlap с исключением холодной полосы. После отпускания worker проверены latest geometry/line/mask, mask revision, реальные mask/составные color pixels и occlusion здания.
2. Изменение stamp и удаление источника одновременно с zoom: готовый viewport не возвращает старые пиксели через fallback.
3. Отсутствующий исходный файл: источник не ready, успешного импорта нет; отдельно проверены предел кольца и отсутствие имён/путей в export.
4. Во время ещё активного multi-touch линия получает актуальный zoom, маска — желаемый viewport. Затем line worker отпускается отдельно, пока mask worker остаётся заблокирован: проверены публикация актуальной линии и её реальные pixels, отсутствие ложного ready reveal. Во время этого движения нет ожидания idle.
5. Ручной export: системный picker и точный frozen snapshot в выбранном файле.

Готовое старое покрытие при отдалении покрывает лишь географический overlap; тест не требует 100% в новой непокрытой полосе. При длительной блокировке raster может быть увеличенным/мягким; проверка детального актуального изображения выполняется отдельно после остановки. Переходы z12↔13 здесь выполнены на legacy disk-source; переключение файлов pack overview/detail отдельно покрыто прежними cold availability/stress-проверками, а не объявлено тем же multi-touch сценарием.

Финальный release-прогон: восстановление main R2 geometry/line/mask **202.5288 ms**, заданный предел **15 s**. Это native software Canvas/Robolectric/JVM с heap 2g, не телефонный latency budget. Старый stress: dense recovery **196.2994 ms**, detail **184.5761 ms**, UI geometry/crop **0 ms**. Большие экраны 1440×2560 и 2560×3840 повторно прошли в availability **17/17**; ready bytes **25152960 / 25160448**, прежние admission-проверки сохранены.

- Нужна отдельная ручная проверка существующих карт/истории: overview/detail, интенсивный pan/pinch, остановка, актуальность линии и раскрытия, экспорт trace сразу после симптома.
