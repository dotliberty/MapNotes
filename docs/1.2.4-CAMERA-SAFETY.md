# MapNotes 1.2.4 — camera switch safety fix

## Report and confirmed scope

Owner reports camera mode closing when switching front/back or changing camera mode. No ADB devices were attached during this investigation, and no device crash report/logcat was supplied. The exact physical-device exception is therefore not established.

Inspection and regression tests confirmed unsafe transition behavior in the existing code:

- `clearSwitchImage()` immediately recycled a Bitmap after removing its ImageView. A queued drawing operation retaining that Bitmap could no longer draw it. The new native Canvas regression retains a reference, clears the overlay and draws the queued frame successfully after the fix.
- The transition rotated the live Camera2 TextureView in 3D; even without an available snapshot it scheduled the device restart behind a view animation. Hardware output surfaces should not depend on decorative view animations.
- Open/disconnect/error paths disabled readiness but did not consistently enable the existing manual mode-recovery UI.

## Changes

- Overlay cleanup cancels its animator, removes the drawable/View and releases application references without calling Bitmap.recycle(). Renderer/GC lifetime is respected. Surface destruction, pause and device errors all remove overlays.
- Front/back and physical-mode transitions animate only the ImageView snapshot. Live TextureView rotationY stays zero. If no snapshot is available or system animations are disabled, device restart proceeds immediately.
- The delayed transition boundary has active/switching/generation guards. Repeated taps do not schedule extra device opens; old fade completion cannot clear a newer overlay.
- New ready preview reveals itself beneath a short overlay fade. Animation completion never manufactures Camera2 readiness.
- Open/disconnect/error handling invalidates stale callbacks, releases the failed device and preserves manual camera/mode selection while keeping the shutter disabled. No automatic fallback to a different physical lens was introduced. No finish()/navigation was added to these failure paths.
- Existing camera policy, JPEG orientation, capture guards and source-formatting standard retained. Version stays 1.2.4/code37 before publication.

## Remaining acceptance

Repeat front/back, manual lens/mode, photo size, rapid repeated selection and background/resume on the actual phone. Successful JVM regressions do not establish that the owner's device-specific failure is gone. If it still exits, capture the app's local crash report or logcat rather than treating these tests as device evidence.
