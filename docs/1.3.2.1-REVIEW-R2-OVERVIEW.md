## Исправление и сохранение source invalidation

- Каждый индексированный pack задаёт собственное семейство редакций. Ревизия семейства включает identity manifest, его stamp/размер, bounds/complete, **весь** текущий упорядоченный набор его областей с source path/stamp/bounds/overview/buildings flags и identity eager-подмены, если она есть. Readiness и cache eviction эту ревизию не меняют. Сигнатура строится из уже индексированных полей, без чтения файлов/геометрии на UI.
- Длинные сигнатуры кэшируются до изменения каталога; каждый кадр проверяет точное совпадение identity/порядка/полей областей без повторной конкатенации всего pack. Снимок метаданных использует weak references для Area/eager и не удерживает старый граф координат. Это устраняет введённые первым вариантом повторные строковые allocations на pack с большим числом cells.
- Общий `AtlasReplay` разрешает группировку только при пересечении границы **z12↔13** и только при точном совпадении ревизии того же pack. Legacy/посторонние источники сохраняют проверку точного key. Соседние detail cells одного семейства соответствуют overview, при этом порядок независимых слоёв сохраняется.
- В обоих backend — viewport и memory tiles — старые пиксели ограничены географическим overlap и пересечением bounds редакций. Новая полоса за пределами прежних cells не объявляется готовой. Изменение исходной **или целевой** редакции, состава или порядка индекса разрывает совместимость; удалённая/изменённая геометрия не возвращается через другой файл pack.
- Точный запрос и отмена выполняемой работы по-прежнему используют текущие zoom/dependencies. Семейство служит только проверке происхождения готового fallback, не выдаёт старый raster за детальный актуальный результат.

Ревизия относится к текущему индексу `OfflineAtlas`: обновление/удаление файлов приложения отражается его переиндексацией и заменой atlas. Невидимое изменение содержимого внешним процессом без обновления индекса не превращается здесь в отдельный full-file hash scan каждого кадра. Добавлена консервативная сигнатура всего pack, поэтому изменение даже невидимого его члена может отклонить fallback всего семейства. Бюджеты raster **24/32 MiB** сохранены; общий peak heap этой доработкой не доказан.

## Дополнения trace и сохранение границ сценария

Кольцо остаётся ограниченным **2048** обезличенными событиями. Новые события не содержат source keys, путей или координат.

- `SOURCE/INVALIDATE`: a=причина (1 исчез/изменён старый key, 2 новый key, 3 изменился порядок), b=член pack-family 0/1, c=zoom. Для изменённой ревизии pair видны отклонённые старые и добавленные новые зависимости.
- `VIEWPORT/STATE`: a=zoom, b=sourcesReady, c=1 новый request, 2 уже pending, 3 exact ready, 4 источники unready; служебный STATE с token=0 имеет c=5 pause, 6 close.
- `VIEWPORT/REPLAY`: a=ready zoom, b=непустое покрытие, c=0 exact, 1 нет ready, 2 style, 3 нет overlap, 4 source invalidation, 5 совместимый переход редакций, 6 обычный replay.
- `VIEWPORT/CANCEL`: прежние причины 1–6 дополнены **7** collected source, **8** coalesced latest, **9** pause, **10** incomplete/read error, **12** OOM. Pending request больше не исчезает молча при coalescing/pause; запись и cancellation counter проверены отдельным тестом. OOM не обнуляет чужой более новый current request.
- `TILE/CANCEL` фиксируется в каждой ветке и при снятии queued job: a=1 close, 2 generation, 3 zoom, 4 dependencies, 5 collected source, 6 crop/not-ready, 7 work admission, 8 вне visible/prefetch ring, 9 вытеснение prefetch из очереди, 10 OOM; b=zoom, c=color pass. `TILE/FINISH` отдельно сообщает pending/workBytes/close. Отмена больше не выводится постфактум лишь из `valid()` в finally.
- `TILE/STATE` сообщает unready dependency. `LINE/STATE` различает duplicate/ready/unusable/clear/close; `LINE/CANCEL` дополнен coalescing=5. `MASK/STATE` различает отсрочку программной анимации, running worker и состояние drawn mask: none, stale revision, stale zoom, complete, preview.

Границы тестового сценария сохранены **отдельными файлами**, поэтому конец не вытесняет начало: `saved-pack-…-start.txt` содержит frozen prefix с `DOWN/POINTER_DOWN`; `…-end.txt` — snapshot после `POINTER_UP/UP`; обычный `…-after.txt` — восстановление. Для 110000-точечного сценария: `render-tests/build/review-r2/gesture-start.txt` (готовая исходная сцена), `gesture-input-start.txt` (первые multi-touch input), `gesture-end.txt` (конец движения), `gesture-trace.txt` (восстановление). Это checkpoints регрессии; runtime ручной экспорт по-прежнему ограничен текущим кольцом.
