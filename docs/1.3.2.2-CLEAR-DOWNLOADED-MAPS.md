**Явное изменение настройки:** сеть карты ставится на паузу, чтобы области/спутник/автоматические улицы не появились сразу снова. Это заранее написано в подтверждении и после успеха. Возобновление — существующая кнопка **«Сеть»** на карте. Пауза сохраняется через restart; после её явного снятия новое скачивание той же области работает. Сохраняемые пользовательские точки позволяют заново построить линию/раскрытие; новые производные данные нового поколения могут затем перестраиваться из сохранённой истории и подключённой карты.

## Lifecycle и защита от поздних действий

1. `DownloadedMaps.beginClear` атомарно меняет поколение и устанавливает `clearing`. Под коротким state lock нет file IO. UI не ждёт IO-lock или завершения worker.
2. Сохранение/создание/удаление повреждённых файлов выполняется с read-lease поколения. Cleaner в фоне получает exclusive IO-lock, поэтому уже начатое IO заканчивается до удаления. Новая попытка старого поколения не проходит ни до, ни после захвата lease. Это распространяется на Transfer.prepare/save/discard, BuildingFetch, спутниковый/растровый writer, atlas import, disk cursor и reveal transaction/read/write.
3. В фоне сохраняется маркер незавершённой очистки, подтверждается сохранение паузы сети, отменяется активный сервис/соединения. Сетевой worker может физически завершиться позже: его поколение уже отозвано. Вновь запускать worker в том же экземпляре сервиса, пока старый жив, нельзя. Старый finally не сбрасывает running/status нового сервиса; поздняя UI-остановка проверяет поколение.
4. Все живые MapView подписаны на смену состояния через weak registry. Они сбрасывают bitmap/pending/error/retry/building state, старый atlas, ready mask/history и memory visibility cache. Epoch каждого задания захватывается **при постановке**, а не читается заново после очистки. Старые tile results/error callbacks не возвращают файлы, bitmap или retry status; старый BuildingFetch не сбрасывает флаг нового запроса.
5. Индексирование/поздний callback проверяют и ticket, и поколение. Очистка заставляет последующее индексирование работать в фоне даже у compatibility MapView. Закрытие отложенного atlas идёт в worker. Старые mask frames отменяются также по поколению. Новое состояние после завершения перечитывается во всех живых views, включая Activity, созданную во время cleanup.
6. Старые OfflineAtlas закрываются в фоне. Disk cursors держат IO-lease до освобождения reader/file handle; файлы не удаляются раньше выхода reader. Закрытие derived files вынесено из LRU monitor. Перед удалением reveal DB старые транзакции завершаются, все старые зарегистрированные RevealCache закрываются; старый экземпляр не может открыть базу заново.
7. Отдельный короткий publish-lock защищает только изменение памяти/публикацию. Сохранение preferences, notification calls и дисковое удаление не удерживают его. Persist сетевой настройки также вынесен из monitor списка соединений, чтобы UI-отмена не ждала fsync worker.

Ошибки delete/list/reset/commit дают неуспешный Result, а не полный успех. Попытка удалить остальные целевые файлы продолжается при локальной ошибке удаления. После ошибки операция допускает повтор. Маркер `downloaded-maps/incomplete` переживает потерю in-memory Result; остатки снова видны обычному индексированию после запуска. При невозможности записать паузу сети файловая очистка не начинается. Это не транзакционная замена всего каталога: при ошибке могут остаться отдельные исходные файлы, что прямо сообщается в UI.

- `finishTileRequest(key, expected)` вызывается без предварительной внешней проверки из обоих finally. Внутри `DownloadedMaps.publish(expected, …)` одновременно проверяется актуальность/владение view и выполняется `pending.remove(key)`.

### Реализация

- `OfflineAtlas`: явный `CancellationException` для закрытого atlas, отозванного поколения и прерывания при wall query/import. Проверки до запроса, после чтения и после импорта не позволяют вернуть частичный набор или успешные пустые стены. Отмена импорта не записывается как постоянный `FAILED`; `importingGeometry` снимается в прежнем finally. Настоящие ошибки IO остаются ошибками, что отдельно проверено повреждённым disk record.
- `MapView.routeWorker`: принимает только явный сигнал отмены; прежний finally ставит UI-завершение, сбрасывает `rendering` и учитывает отменённый кадр. Публикация по-прежнему проверяет актуальность исходного frame; старые preview/history не возвращаются после очистки.
- `RouteFrame`: отмена не является обычным ранним выходом из `add`; проверка выполняется также после последней точки. `complete` устанавливается только после нормального завершения build и финализации кэша. Поздний cache put ограждён `DownloadedMaps.publish` исходного поколения, чтобы не наполнить общий memory visibility cache после его очистки.
- `RevealCache.end(success)`: незавершённый/отменённый frame откатывает транзакцию, успешный актуальный frame подтверждает её. `endTransaction` и освобождение lease находятся в finally.
