# 1.2.0-beta.3 — камера и стабильная debug-подпись

Дата: 08.11.2026. База: main c625564 (предыдущий 2d5f665). versionCode 30.

## Причина и исправление

В beta.2 previewMatrix рассматривала вход TextureView как сырой sensor buffer: заново применяла SENSOR_ORIENTATION и отражение фронтальной камеры. Camera2 producer/TextureView уже учитывает sensor orientation и стандартное front mirroring. Дополнительный поворот/отражение давали неверную ориентацию, особенно заметную после блокировки UI. Это не исправляется постоянным поворотом на 180° для одной модели телефона.

Теперь матрица работает в координатах уже ориентированного TextureView: восстанавливает правильное соотношение сторон, компенсирует только display rotation (-display), центрирует изображение с FIT_CENTER. Повторного sensor rotation и mirror нет. Relative rotation для размеров рассчитывается по SENSOR_ORIENTATION и display rotation с front/back sign. AspectTexture использует relative rotation, а не догадку по ширине/высоте окна. Полный выбранный preview сохраняется без дополнительного crop/stretch. Выбор preview по JPEG-aspect и существующий цифровой crop по active array сохранены. Метаданные берутся у выбранной physical/logical камеры, не по названию устройства.

JPEG_ORIENTATION остаётся независимым: OrientationEventListener измеряет физический угол, даже при locked UI; jpegRotation использует sensor + device для back и sensor - device для front. Preview не поворачивается от физического угла, когда display/UI заблокированы.

Первичные источники Android, проверены при работе:
- https://developer.android.com/media/camera/camera2/camera-preview — TextureView, relative rotation, FIT_CENTER.
- https://developer.android.com/reference/android/hardware/camera2/params/OutputConfiguration#MIRROR_MODE_AUTO — default front horizontal mirror, no back mirror.

## Щипок

ScaleGestureDetector подключён непосредственно к preview. Мультипликативный zoom ограничен метаданными камеры (ratio API либо crop); линза автоматически не переключается. Оставлен доступный через кнопку slider. Захват, неготовая камера, неподдерживаемый zoom и сменившийся generation блокируют жест; cancel завершает его. Невалидные scale factors игнорируются. Регрессия отправляет реальные двухпальцевые MotionEvent через View.dispatchTouchEvent и проверяет изменение zoom, cancel и отсутствие однопальцевого zoom.

## Подпись: блокер обновления beta.2

Старый tools/build.py --debug создавал disposable-debug.jks внутри очищаемого sdk-build и удалял его после подписи. Одинаковый package не обеспечивал одинаковую подпись; обновление beta.2 новой случайной подписью невозможно. Удалённый приватный ключ beta.2 этим изменением не восстановлен.

Исправленный --debug принимает только существующий постоянный ~/.android/debug.keystore вне checkout. Используются стандартные публичные Android debug alias/password. До сборки keytool проверяет доступность/password/alias; ошибка завершает сборку, без регенерации или удаления ключа. Генерации ключа нет вообще. Debug запрещает release signing arguments. Релизные ключи и секреты в этой работе не читались и не использовались.

Новую debug identity не создавали и не использовали: отдельное разрешение владельца не получено. Собран только UNSIGNED APK; он не устанавливается и НЕ является готовым обновлением beta.2 либо релизного приложения. Пользовательская установка и данные не тронуты. Никакого push.

## Осталось

Физическая приёмка на телефоне НЕ выполнена. Robolectric не воспроизводит реальный Camera HAL: проверить back/front/physical lenses, старт с разных display orientations, верх/низ и зеркало, JPEG во всех физических углах при locked UI, щипок и соответствие сохранённого кадра preview. Обновление существующей beta.2 требует её исходного сертификата; восстановление удалённого ключа невозможно из APK. Решение о новой постоянной debug identity/доставке — отдельно с Димой, без удаления приложения или данных в этой работе.
